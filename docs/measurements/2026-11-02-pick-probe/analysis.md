# 분석 노트 — 2026-11-02 LLM 직접 선곡 프로브

`summary.md`는 스크립트가 낸 1차 집계다. 이 노트는 그 수치를 읽을 때 필요한 정정과, 같은 선곡을 해석기 v2로 다시 해석한 결과를 담는다(11/3 작성).

## 1. `summary.md`의 해석률은 부풀려져 있다

요약표의 해석률 64~70%는 "iTunes가 곡명이 맞는 무언가를 돌려줬다"를 센 값이다. 커버·MR·자장가·동명이곡도 성공으로 들어간다.

원곡 기준으로 다시 세면 다음과 같다. 판정은 자동 근사다: 해석됨 + 다른 가수(커버·연주곡 등 수동으로 모은 26개 아티스트)가 아님 + 버전 표기(instrumental·MR·live·remix·lullaby·8-bit 등)가 없음.

| 모델 | 요약표 해석률 | 원곡 기준 | 한국 곡 중 곡명이 한글인 곡 |
| --- | --- | --- | --- |
| gpt-4.1-mini | 70% | 59% | 18% |
| gpt-6-luna | 69% | 58% | 21% |
| gpt-6.1-terra | 64% | 53% | 10% |

## 2. 원인은 LLM 환각이 아니라 해석기

같은 곡이 영문 곡명으로 요청되면 해석되고, 한글 곡명으로 요청되면 실패했다(빨간 맛 ↔ Red Flavor, 밤편지 ↔ Through the Night). 실패한 곡 대부분은 실제 히트곡이다.

1. **KR 스토어 검색이 항상 0건**: 한글·영문·로마자 검색어 모두 0건. 같은 KR 스토어의 lookup(trackId 조회)은 정상이다(11/3 확인). 원인은 알 수 없다(Apple 쪽 또는 이 IP).
2. **US 스토어는 영문 현지화 곡명을 돌려준다**: 한글 검색어로도 곡은 찾지만 `좋은 날`이 `Good Day`로 와서 곡명 대조에서 탈락한다. Apple의 영문 곡명은 번역이 아니라 임의 표기다(너를 만나 → Me After You).
3. **아티스트 검증이 없다**: 곡명만 맞으면 채택해서, 한글 이름을 쓰는 커버·MR이 통과했다(모델당 오매칭 40~48건).

당시 운영 코드(Last.fm 하이브리드의 iTunes 해석)도 같은 결함을 갖고 있었다.

## 3. 해석기 v2로 같은 선곡 재해석 — `resolve-v2.json`

해석기 v2(커밋 `07c0c36`)의 동작은 다음과 같다.

1. US 검색 1회(limit 5)
2. 미국 스토어 표기로 곡명·아티스트를 대조
3. 실패하고 요청에 한글·일본어가 있으면, 후보 trackId를 KR·JP 스토어에서 lookup해 현지화 표기로 다시 대조
4. 일본 곡은 마지막에 JP 스토어 검색
5. 버전 필터(MR·연주곡은 제외, Live·Remix는 원곡이 없을 때만 채택)

운영 코드 그대로 실행하되, 네트워크 대신 11/3에 수집한 iTunes 원본 응답을 재생해 측정했다(곡당 평균 1.58회 호출).

| 모델 | 기존 해석기 | v2 | 모드 10곡 채움(12곡 중 정답) |
| --- | --- | --- | --- |
| gpt-4.1-mini | 59% | 90% | 6/52 → 47/52 |
| gpt-6-luna | 58% | 95% | 3/52 → 51/52 |
| gpt-6.1-terra | 53% | 93% | 1/52 → 49/52 |

**주의**: v2의 규칙은 이 547곡의 실패 사례를 보며 다듬었다(튜닝셋 = 평가셋). 처음 보는 곡에서의 성능은 `../2026-11-03-holdout/analysis.md`를 본다.

## 4. 남은 실패

- 약 절반은 프롬프트 표기 지침("한국 곡은 공식 한글 표기")이 만든 음차·번역이다. 예: `트와이스`(공식 TWICE), `우주를 건너`(공식 Across the universe). Apple은 KR 스토어에서도 이들을 영문으로 등록한다. 추천 재설계에서 "음원 사이트 공식 표기 그대로, 음차·번역 금지"로 고친다.
- 나머지는 검색 상위에 원곡이 없는 곡(Green Day `American Idiot`은 같은 앨범의 다른 곡과 자장가 커버만 나옴)과 검색 결과 0건(긴 한글 곡명)이다.
